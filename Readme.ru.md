### Библиотека для `.env`, которая возвращает вам ваш файл.

Прочитать `.env` умеет любая библиотека. **Записать обратно** — почти никакая. Загрузите конфиг в map, выгрузите на
диск — и аккуратно собранный файл вернётся отсортированным, без кавычек, без комментариев, чужим. Поэтому `.env` никто
не правит программно. Их правят руками, всегда.

`envi` моделирует сам документ, а не только значения. Комментарии, секции, пустые строки, стиль кавычек и даже CRLF
переживают путь туда и обратно. Меняете один ключ — получаете диф в одну строку.

---

## Увидеть разницу

Дан `.env`:

```dotenv
###   ---[ Application ]---   ###
# Human readable name
APP_NAME="My App"
APP_DEBUG=false
```

Переключаем один флаг:

```go
env, _ := envi.Load(".env")
env.Set("APP_DEBUG", "true")
envi.Save(env, ".env")
```

**С `envi`** — в дифе ровно то, что вы изменили:

```diff
  ###   ---[ Application ]---   ###
  # Human readable name
  APP_NAME="My App"
- APP_DEBUG=false
+ APP_DEBUG=true
```

**С циклом «загрузить в map и выгрузить»** — в дифе весь файл:

```diff
- ###   ---[ Application ]---   ###
- # Human readable name
- APP_NAME="My App"
- APP_DEBUG=false
+ APP_DEBUG="true"
+ APP_NAME="My App"
```

Ради этой разницы библиотека и существует, и держат её property-тесты, работающие на каждом пуше:
наш собственный вывод всегда перечитывается в те же байты, а перечитанный документ всегда даёт те же строки, значения и
тени, что держал, — то есть по дороге наружу ничего не может тихо пропасть. Оба свойства непрерывно фаззятся.

Корректно оформленный файл возвращается байт в байт. Два входа перестраиваются, а не воспроизводятся, и библиотека
говорит об этом прямо: ключ, которому **дважды** задано живое значение — второе побеждает, первое становится тенью над
ним (`Check` считает это ошибкой), — и файл, **смешивающий CRLF и LF**, который приводится к первому встреченному
окончанию. Ни в одном из случаев ничего не теряется.

## Установка

```shell
go get github.com/efureev/envi/v2
```

```go
import envi "github.com/efureev/envi/v2"
```

Требуется Go 1.26. **Ноль зависимостей** — и в библиотеке, и в её тестах.

Суффикс `/v2` остаётся в пути импорта, хотя код лежит в корне репозитория. Просто так Go называет мажорную версию, и
искать одноимённый каталог не нужно.

## Два способа использования

### 1. Просто дайте мне конфиг, типизированный

Большинству программ нужно только это. Подпакет `bind` самодостаточен: он может быть единственной частью `envi`, которую
вы импортируете.

```go
import "github.com/efureev/envi/v2/bind"

type Config struct {
Name  string        `env:"APP_NAME"`
Port  int           `env:"APP_PORT,required"`
TTL   time.Duration `env:"CACHE_TTL,default=30s"`
Hosts []string      `env:"HOSTS,separator=;"`
DB    struct {
Host string `env:"HOST,required"`
Port int    `env:"PORT,default=5432"`
} `env:"DB"`
}

var cfg Config
if err := bind.Load(&cfg, bind.WithOptionalFiles(".env"), bind.WithEnviron()); err != nil {
log.Fatal(err)
}
```

Файлы читаются по порядку, каждый следующий перекрывает предыдущий; окружение процесса перекрывает их все. Отсутствие
необязательного файла — не ошибка: это контейнерный случай, где всё приходит через окружение.

**Ошибки приходят все сразу**, а не по одной за запуск:

```
bind: 2 fields failed:
  - Port (APP_PORT): strconv.ParseInt: parsing "eighty": invalid syntax
  - DB.Host (DB_HOST): bind: required value is missing
```

Из коробки: все размерные целые и вещественные, `bool`, `string`, `time.Duration`, срезы, карты, указатели, вложенные
структуры, `[]byte` и всё, что реализует `encoding.TextUnmarshaler`, — а это попутно покрывает `time.Time`, `net.IP` и
большинство ID-типов. Нет тега? Ключ выводится из имени поля: `AppName` → `APP_NAME`, `HTTPPort` → `HTTP_PORT`.

Всё остальное закрывается одной строкой. `url.URL` — тип, на который натыкаются первым: `UnmarshalText` у него нет, и
добавить его извне пакета нельзя.

```go
bind.Load(&cfg, bind.WithConverter(url.Parse))
```

Это покрывает поля `*url.URL`, а заодно `[]*url.URL` и `map[string]*url.URL` — регистрировать что-то ещё не нужно.
Зарегистрированный тип побеждает и собственный `UnmarshalText`, поэтому тип, чья текстовая форма не годится для
конфига, можно читать здесь иначе, не меняя сам тип.

Нужно несколько? Передайте по одному на тип. Три стоят не дороже одного: то, что конвертер отключает — кэш плана
типа, — отключается первым и повторно не отключается остальными.

```go
// net.ParseCIDR возвращает три значения и не подходит под func(string) (T, error).
// Обёртка — и есть вся адаптация.
parseCIDR := func(s string) (*net.IPNet, error) {
    _, network, err := net.ParseCIDR(s)
    return network, err
}

err := bind.Decode(src, &cfg,
    bind.WithConverter(url.Parse),
    bind.WithConverter(parseCIDR),
    bind.WithConverter(parseSeverity),   // ваш собственный тип, метод не нужен
)
```

Каждый сбойный конвертер по-прежнему сообщает о своём поле, поэтому один прогон показывает всю картину:

```
bind: 2 fields failed:
  - Endpoint (ENDPOINT): parse "://nope": missing protocol scheme
  - LogLevel (LOG_LEVEL): unknown severity "shout"
```

Впрочем, сперва проверьте: многие типы уже умеют читать себя сами. `regexp.Regexp` умеет, а `url.URL`, `net.IPNet` и
`time.Location` — нет.

Стоит знать, от чего это спасает: **без** конвертера такое поле не остаётся пустым — оно разбирается по частям, а его
собственный ключ игнорируется. Поле `*url.URL` с ключом `ENDPOINT` соберётся из `ENDPOINT_SCHEME` и `ENDPOINT_HOST`,
молча и без ошибки.

### 2. Работать с файлом как с документом

```go
env, err := envi.Load(".env", ".env.local") // слияние, побеждает последний

env.Set("APP_PORT", "8080")                   // создать или обновить
env.Delete("APP_DEBUG")
env.Get("APP_URL").SetComment("staging only")

envi.Save(env, ".env") // атомарная запись
```

Полезно там, где сегодня инструментов просто не пишут: инсталляторы, создающие `.env`; CLI, переключающие фича-флаг;
проверки в CI, сверяющие `.env` с `.env.example`; миграции, переименовывающие ключ по десяткам репозиториев.

## Прибраться в файле, который расползся

Живые `.env` дрейфуют. Ключи оседают там, куда их положила последняя спешная правка, префиксы разъезжаются, секции
теряют своих. `Regroup` собирает все ключи с общим префиксом в один блок, где бы они ни лежали; `Tidy` делает то же
самое и сортирует.

```dotenv
###   ---[ Application ]---   ###
APP_NAME=one
DB_HOST=localhost
APP_DEBUG=false
DB_PORT=5432
LONE=x
```

```go
env, _ := envi.Load(".env")
env.Tidy()
envi.Save(env, ".env")
```

```dotenv
###   ---[ Application ]---   ###
APP_DEBUG=false
APP_NAME=one

DB_HOST=localhost
DB_PORT=5432

LONE=x
```

Заголовки секций переезд переживают, и точно так же его переживают комментарии строк и тени. Сколько строк нужно, чтобы
образовался блок, решаете вы: `env.Regroup(envi.WithGroupThreshold(3))` распустит оба блока выше, потому что ни в одном
нет трёх строк, а заголовок не выбросит, а понизит до обычного комментария на первой строке, которую тот вводил.

Переехавшая строка отдаёт своё побайтное представление: записанные над ней пустые строки и комментарии описывали то
место, где она раньше стояла. Документ, уже находящийся в порядке, остаётся нетронутым и по-прежнему пишется байт в
байт, поэтому вызвать `Regroup` перед сохранением ничего не стоит, когда делать нечего.

## Проверить файл, прежде чем ему доверять

`Check` читает и проверяет за один проход. В отличие от `Parse` он не останавливается на первой некорректной строке —
один вызов сообщает обо всём, что в файле не так.

```go
env, report, err := envi.CheckFile(".env") // err — только про ввод-вывод
if !report.OK() {
report.Text(os.Stderr)
os.Exit(1)
}
```

```
1: warning: key-not-canonical: key is written as "app-name" (APP_NAME)
2:9: error: syntax: unterminated quoted value
4: error: duplicate-key: key is already defined on line 3, and that value is discarded (APP_URL)
5: warning: empty-value: value is empty (EMPTY)
6: warning: unquoted-value: bare value holds '$' (PASS)
7: error: key-invalid: key is not a usable environment variable name (1BAD)
```

Строка и колонка — в том виде, который редакторы и логи CI превращают в ссылку. `report.JSON(w)`
пишет те же находки объектами; `report.Err()` сворачивает их в одну ошибку для тех, кому нужно лишь понять, продолжать
ли.

| Правило             | Уровень | Что ловит                                                           |
|---------------------|---------|---------------------------------------------------------------------|
| `syntax`            | error   | строку, которая не разбирается, — все такие, а не только первую     |
| `duplicate-key`     | error   | ключ, которому дважды задано живое значение: первое молча пропадает |
| `key-invalid`       | error   | имя, которое не примет ни один шелл, например начинающееся с цифры  |
| `key-not-canonical` | warning | нижний регистр, дефисы — всё, что будет переписано при выводе       |
| `empty-value`       | warning | живую строку, где справа от `=` ничего нет                          |
| `unquoted-value`    | warning | голое значение с `$`, `` ` ``, кавычкой или обратным слешем         |

Закомментированный вариант рядом с живым значением — это *тень*, идиома, вокруг которой построен формат, и дубликатом
она не считается никогда. Правила отключаются по имени:
`envi.WithoutRules(envi.RuleEmptyValue)`.

Документ возвращается тоже, вместе с неразобранными строками, поэтому проверить файл и записать его обратно никогда не
удалит то, что не удалось понять. Для документа, уже находящегося в памяти,
`env.Check()` выполняет те правила, которым не нужен исходный текст.

## Сравнить два файла

`Diff` отвечает, что изменилось в **конфигурации**, — не что изменилось в файле. Для второго вопроса у вас уже есть
`git diff`.

```go
before, _ := envi.Load(".env.bak")
after, _ := envi.Load(".env")

fmt.Print(before.Diff(after))
```

```
- APP_DEBUG="false"
~ APP_URL: "https://a.example" -> "https://b.example"
+ APP_PORT="8080"
```

Комментарии, тени, стиль кавычек, принадлежность блоку и порядок не дают ничего: это то, как документ записан, а не то,
что он настраивает. Значения в кавычках, потому что иначе пустое значение неотличимо от неизменившегося.

Результат — `*Delta`, той же формы, что возвращает `Check`: `All()`, `Len()`, `Count(kind)`, `Empty()`, `Text(w)`,
`JSON(w)`. Именно поэтому проверка в CI, ради которой всё и делалось, укладывается в несколько строк:

```go
for c := range example.Diff(actual).All() {
    switch c.Kind {
    case envi.ChangeRemoved:
        fmt.Println("нет в .env:", c.Key)          // задокументирован, но не задан
    case envi.ChangeAdded:
        fmt.Println("не описан:", c.Key)           // задан, но нет в примере
    case envi.ChangeChanged:
        // Отличие реального значения от заглушки — это норма.
    }
}
```

Что стоит знать: **закомментированная строка не настраивает ничего**, поэтому закомментировать ключ — это удаление. Так
на это смотрит `Export`. И осознанно не так, как смотрит `Lookup`, который значение закомментированной строки всё же
возвращает, — `Diff` отвечает на вопрос про конфигурацию.

## Что вы получаете сверх map

|                     |                                                                                            |
|---------------------|--------------------------------------------------------------------------------------------|
| **Комментарии**     | Заголовки секций, комментарии к строкам и хвостовые — каждый остаётся на месте             |
| **Тени**            | `# REDIS_HOST=redis` рядом с живым значением — полноценное понятие, а не потерянная строка |
| **Порядок**         | Порядок исходника сохраняется; сортировка — то, о чём просят, а не побочный эффект         |
| **Блоки**           | Строки с общим префиксом собираются в `Block`, к которому можно обращаться как к целому    |
| **Форматирование**  | Стиль кавычек, отступы, пустые строки, CRLF против LF — всё воспроизводится                |
| **Уборка**          | `Regroup` и `Tidy` возвращают расползшийся файл в порядок вместе с комментариями           |
| **Валидация**       | `Check` сообщает обо всех проблемах за один проход, со строкой и колонкой                  |
| **Позиции**         | Некорректная строка сообщает свою строку *и* колонку, а не «invalid format»                |
| **Без ограничений** | Нет предела в 64 КиБ на строку; сертификат в base64 одним значением разберётся             |

```go
row := env.Get("REDIS_HOST")
row.Value()   // "127.0.0.1"
row.Comment() // "for docker"
for alt := range row.Shadows() {
fmt.Println(alt) // redis
}
```

## Быстро, и это измерено

Парсер — написанный руками однопроходный сканер. Регулярных выражений нет нигде в модуле.

Файл в 1000 строк, Go 1.26, Apple M5 Pro, `benchstat`, `-count 8`:

| Операция                      |                  Время | Аллокаций |
|-------------------------------|-----------------------:|----------:|
| Разбор                        | **237 µs** (134 МиБ/с) |     4 405 |
| Запись                        |            **22.6 µs** |         5 |
| Поиск                         |            **27.8 ns** |     **0** |
| Заполнение 50 полей структуры |             **1.0 µs** |         2 |

Поиск — O (1) и без аллокаций. `bind` разбирает раскладку каждого типа один раз и кэширует её, поэтому тысячный конфиг
стоит столько же, сколько второй.

Отсутствие `regexp` — решение измеренное, а не стилистическое: компиляция шаблона, чтобы разобрать одну строку, стоит
5.5 µs и 146 аллокаций против 4.5 ns и нуля у разбора той же строки вручную. Вот и весь разрыв, ради которого сканер
написан именно так.

## Сделано так, чтобы доверить этому свой конфиг

- **Ноль зависимостей.** Нечего аудировать, нечего обновлять, нет цепочки поставок.
- **Непрерывный фаззинг.** В CI работают семь фаз-таргетов: парсер не паникует, его собственный вывод всегда
  перечитывается в тот же документ, **запись документа никогда не выбрасывает то, что он держит**, уборка не меняет
  смысла документа, а проверка сходится с парсером в том, что формат допускает. Каждый вход, который когда-либо отверг
  фаззер, закоммичен как постоянная регрессия.
- **Проверено на гонки и на перемешивание.** `go test -race -shuffle=on` на Linux, macOS и Windows. В пакете нет
  изменяемого глобального состояния, поэтому две библиотеки в одном процессе не могут подраться за настройки.
- **Атомарная запись.** `Save` пишет во временный файл и переименовывает его. Прерванный запуск не оставит вам половину
  `.env`.
- **Документировано.** У каждого экспортированного символа есть doc-комментарий, это проверяет линтер.

## Обзор API

```go
// Чтение
env, err := envi.Parse(r) // любой io.Reader
env, err := envi.ParseString(s)
env, err := envi.ParseBytes(b)
env, err := envi.Load(".env", ".env.local")

// Запись
env.WriteTo(w)    // io.WriterTo
env.MarshalText() // encoding.TextMarshaler
envi.Save(env, ".env")

// Поиск — O(1), ключи нормализуются, поэтому написание не имеет значения
env.Lookup("app-port") // "8080", true
env.Get("APP_PORT")                             // *Row
env.Block("APP")                                // *Block

// Обход — без промежуточных срезов
for key, value := range env.All() { }
for row := range env.Rows() { }
for item := range env.Items() { }               // *Row либо *Block

// Правка
env.Set("K", "v")
env.Add(envi.NewRow("HYPE", "false"))
env.Delete("K")
env.DeleteBlock("APP")
env.Merge(other)
env.Export(true) // в os.Environ

// Упорядочивание
env.SortByKey() // отсортировать, группировку не трогать
env.Regroup() // собрать разбросанные префиксы в блоки
env.Tidy()    // перегруппировать, затем отсортировать

// Проверка
env, report, err := envi.CheckFile(".env") // все проблемы, а не только первая
report.OK()                                // ошибок нет, предупреждения допустимы
report.Text(os.Stderr)
report.JSON(w)
report.Err() // nil либо одна ошибка, называющая все
env.Check()  // правила, которым не нужен исходный текст

// Сравнение — что изменилось в конфигурации, а не в файле
d := before.Diff(after)         // *Delta
d.Empty()                       // оба настраивают одно и то же
d.Count(envi.ChangeAdded)
d.Text(os.Stderr)
for c := range d.All() { }      // Kind, Key, Old, New
```

Форматирование выбирается для операции, а не глобально:

```go
envi.NewEncoder(w,
envi.WithQuoting(envi.QuoteAlways),
envi.WithOrder(envi.OrderSorted),
envi.WithComments(false),
).Encode(env)
```

Ошибки несут позицию:

```go
var syntaxErr *envi.SyntaxError
if errors.As(err, &syntaxErr) {
fmt.Println(syntaxErr.Line, syntaxErr.Col, syntaxErr.Msg)
}
```

Полный справочник и запускаемые примеры: [pkg.go.dev](https://pkg.go.dev/github.com/efureev/envi/v2).

## Многопоточность

`*Env` — изменяемый документ, защищайте его как любой другой. `Decoder`, `Encoder` и `bind` не делят состояние между
экземплярами, поэтому разбирать, записывать и заполнять структуры из многих горутин одновременно безопасно.
